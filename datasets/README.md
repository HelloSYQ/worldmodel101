# Datasets and environments for world models

> Reference for the whole course. Each phase in the [syllabus](../README.md#syllabus-and-progress) has a *Data:* line that links here. Phase D teaches how to judge a dataset; this file is the catalog it draws on.

**Main idea.** A world model is trained to reproduce the data it sees. It can't learn dynamics the data never shows: actions nobody took, states nobody visited, futures that were never recorded. Before reading a world-model paper's results, find out what it was trained on and who collected that data.

---

## 1. Environments vs. datasets

| | **Environment** (a simulator you can query) | **Dataset** (a fixed log) |
|---|---|---|
| Interface | `obs, rew, terminated, truncated, info = env.step(a)` | a file of recorded episodes |
| Who picks the actions | you, any time, any policy | whoever collected it, once |
| "What if I had done $a'$ instead?" | run it and see | unobserved: the counterfactual was never recorded |
| Typical setting | online RL (Phases 2–4) | offline RL, video pretraining (Phases 5–8) |

A world model trained on a dataset tries to turn that dataset into an environment. It can only be trusted where the dataset has coverage. Outside that region the model is guessing, and a planner or policy optimized against it will find those guesses and exploit them (Phase 2: model exploitation).

## 2. Seven questions to ask of any world-model dataset

| # | Question | Why it matters for a world model |
|---|---|---|
| 1 | **Observations:** what does the model see (state vector, pixels, multi-camera video, tokens, CSI)? Is the state fully observed? | Decides the modelling problem: dynamics regression (full state) vs. filtering a latent state (POMDP, Phase 0.6 → Phase 3) |
| 2 | **Actions:** are actions logged, and at what rate relative to observations? | No actions means action-free video. You can still learn $p(o_{t+1}\mid o_{\le t})$, but not "what if I do $a$" until you recover actions (inverse dynamics as in VPT, or latent actions as in Genie and LAPA) |
| 3 | **Task signal:** reward, success flag, language instruction, or nothing? | Needed to train a policy in imagination; without it the model is only a simulator |
| 4 | **Collector:** who chose the actions: random, exploration, scripted, expert, human players, or the learning agent itself? | Sets coverage. A model trained only on expert driving has never seen a crash, and a model trained only on random play has never seen the later levels |
| 5 | **Episodes:** boundaries, length, frame rate, resets | Sets the longest horizon you can train and test on, and whether "the episode ended" is something to predict |
| 6 | **Stochasticity:** how much of the future is not determined by the past and the action? | Deterministic physics (DMC) can be learned with a point prediction. Multi-agent games, driving and fading channels need a distribution over futures (Lesson 0.1, the blur problem) |
| 7 | **Scale and access:** hours / frames / trajectories, storage, compute, license, released or not | Decides whether you can reproduce the result, inspect a sample, or only read about it |

### Worked example: the CS:GO data behind DIAMOND (Phase 6)

| # | Answer | Consequence |
|---|---|---|
| 1 | RGB frames at 16 Hz from one map (Dust II) | The model only ever learns one map |
| 2 | Keyboard and mouse logged every frame | Action-conditioned, so the model is playable |
| 3 | None needed | It's used as a simulator to play in, not to train an RL agent |
| 4 | Human players on online servers | Mostly competent play. Rare behaviour (walking into a wall, standing still) is where the model is weakest, and it's what a new player tries first |
| 5 | 5.5M frames in total; 0.5M (500 episodes) held out for testing | About 1,000 frames per episode; the model conditions on only a short window of past frames, so it can't remember anything older |
| 6 | Other players and their choices | Futures are genuinely multi-modal, which favours a diffusion model over MSE regression |
| 7 | 95 h released by Pearce & Zhu (2022); DIAMOND trains on 87 h, about 12 days on one RTX 4090 | Reproducible on one GPU, not on a CPU |

Reported failures (passing through walls, inconsistent gravity, forgetting what's behind you) follow from answers 4 and 5.

### Tier W: The radio channel

Track W data. The environment is the channel and the UE's mobility, observations are CSI-RS / SSB measurements, and actions are beams or MCS choices.

| Dataset | What's recorded | Collected by | Use in the course | Access |
|---|---|---|---|---|
| 3GPP TR 38.901 CDL-A…E / TDL-A…E | standardized stochastic link-level channels: clusters or taps with delays, powers and angles; you set delay spread, UE speed and carrier, which fixes the Doppler | your simulation parameters | default capstone data; the same models companies use in TR 38.843 evaluations | generate with Sionna (NVIDIA, open source), QuaDRiGa, or our own numpy code |
| TR 38.901 system-level models with spatial consistency (§7.6.3) | UMa / UMi / InH channels that evolve consistently as the UE moves | your simulation | realistic mobility | same tools |
| DeepMIMO (Alkhateeb 2019) | ray-traced channels on a dense grid of user positions in fixed scenes; any antenna array and bandwidth | ray tracing | beam prediction; build sequences by moving along a path through the grid | open; Python and MATLAB generators |
| DeepSense 6G (Alkhateeb et al. 2023) | real measurements: mmWave received power across a beam codebook (64 beams in the beam-prediction scenarios), synchronized with camera, lidar, radar and GPS; 40+ scenarios | measurement campaigns (vehicles, pedestrians, drones passing a base station) | real-data test for sensing-aided beam prediction and tracking (BM-Case2-like) | open |
| Sionna RT | differentiable ray tracer: build a site-specific digital twin, move a UE along a path, get the channel sequence | ray tracing | digital twin vs. learned dynamics | open |
| DICHASUS (University of Stuttgart) | measured CSI from a distributed massive-MIMO testbed with ground-truth positions | measurement campaigns | positioning, channel charting | open |

Two notes for the capstone:
- **CDL/TDL channels evolve only through per-ray Doppler within a drop**, so a long sequence is stationary and the cluster geometry never changes. That makes it easy to predict, and a weak test of long horizons. For realistic mobility, use spatial consistency or ray tracing.
- **TR 38.843 has no public dataset.** Companies generated their own data from agreed simulation assumptions, and we follow the same approach.

## 4. Evaluation: metrics and benchmarks

### Metrics

| Family | Metric | What it measures | Watch out for |
|---|---|---|---|
| Per-frame fidelity | MSE / PSNR, SSIM | closeness to the one recorded future, pixel by pixel | **Rewards the blurry mean** (Lesson 0.1): a model that hedges scores higher than one that commits to a sharp but different plausible future |
| Perceptual | LPIPS (Zhang et al. 2018) | closeness in deep-feature space | still compares against a single future |
| Distribution | FID (Heusel et al. 2017), FVD (Unterthiner et al. 2018) | whether generated frames / videos look like samples from the real distribution | can't tell whether a sample actually follows the actions given |
| Controllability | ΔPSNR (Genie): PSNR with inferred actions minus PSNR with random actions | whether the action actually changes the predicted future | — |
| Consistency / memory | revisit tests: leave a place, come back, compare | long-horizon state retention | short context windows fail this by design |
| Probabilistic | NLL, calibration; $k$-step error vs. horizon | honest uncertainty; compounding error (Phase 2) | — |
| Downstream, RL | return in the *real* environment; Atari human-normalized score, aggregated by IQM with bootstrap confidence intervals (Agarwal et al. 2021, `rliable`) | whether the model is useful for decisions | with few seeds, differences are noise; report intervals |
| Downstream, radio | NMSE and SGCS for CSI; Top-$K$ beam accuracy and L1-RSRP difference for beam management (TR 38.843 KPIs) | what 3GPP evaluations report | compare against Kalman / AR and "repeat last measurement" baselines |

| Benchmark | What it tests |
|---|---|
| Physion (Bear et al. 2021) | from video of a physical scene, predict an outcome (will these objects touch?) |

## 5. Formats and tooling

- **Gymnasium:** `obs, reward, terminated, truncated, info = env.step(action)`. `terminated` means the task ended (the pole fell); `truncated` means a time limit cut the episode short. A world model should predict termination, but not truncation, which is a fact about the data collection, not about the world.
- **Minari:** Farama's offline-dataset format and hub, the successor to D4RL.
- **RLDS:** an episode-and-step format on TensorFlow Datasets, used by Open X-Embodiment.
- **LeRobot:** Hugging Face's robot-dataset format (Parquet for states and actions, MP4 for video).

**Course episode format.** All labs from Phase D on save episodes the same way, so that any model can be trained on any dataset:

```
episode_0000.npz
  obs   [T+1, ...]   observations o_0 … o_T   (float32, or uint8 for pixels)
  act   [T, ...]     action a_t, taken after seeing o_t
  rew   [T]          reward r_t for (o_t, a_t)
  term  [T]          True if o_{t+1} is terminal (the task ended)
```

An episode cut off by a time limit simply ends; it isn't marked as terminal.

## 6. What this course runs on a CPU

The labs use Tier 0, small pieces of Tiers 1–2 (Gymnasium, Crafter, a few DMC tasks at low resolution), and Tier W channels we generate ourselves. Everything in Tiers 3–6 is read about, inspected in small samples, or replaced by a toy that keeps the property that matters. For example, action-free web video becomes the bouncing-ball dataset with the actions hidden.
