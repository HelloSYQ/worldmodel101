# worldmodel101

A self-paced course on **world models**, from first principles to current research, in three stages:

1. **Core ideas:** the basic ideas every world model is built from (estimation, latent variables, sequence models, RL, classical dynamics and control)
2. **Data and model families:** the datasets and benchmarks the field runs on, and the model families built on them
3. **New designs:** evaluation, open problems, and designing, testing and defending your own world model

- **Goal:** research-level understanding, ending in an original capstone project
- **Pace:** ~5 h/week, about 23 weeks (we'll revisit the pace as we go)
- **Assumed background:** NR / wireless (estimation, Kalman filtering, linear algebra). No prior ML/RL training experience.

## The organizing grid

A world model answers *"what happens next if I do $a$?"*, i.e. it models

```math
p_\theta(s_{t+1}\mid s_t, a_t), \qquad p_\theta(o_t\mid s_t), \qquad p_\theta(r_t\mid s_t, a_t)
```

and an agent uses it to predict, imagine, plan or simulate. Every paper in this course gets placed on two axes:

| What the model predicts | What it is used for |
|---|---|
| raw observations (pixels / video) | planning (MPC, tree search) |
| latents trained with reconstruction | training a policy in imagination |
| latents trained without reconstruction | acting as an environment / simulator |
| only task quantities (reward, value, policy) | learning representations |
| | generating data, evaluating policies |

A model can only learn what its data shows it. So every paper also gets a third question: **what was it trained on, and who collected it?** The [datasets guide](datasets/README.md) covers how to answer that for any dataset, and catalogs the datasets used in this course.

## How each lesson runs

1. **Intuition:** why the idea exists, what problem it fixes
2. **Math:** derived, not asserted (LaTeX in `notes/`)
3. **Paper walkthrough**
4. **Data:** what the papers train and evaluate on, and what that data does and doesn't let the model learn
5. **Lab:** small CPU-sized experiment in `labs/`
6. **Check questions:** answered in `answers/` before moving on

## Repository layout

```
notes/     one Markdown file per lesson (math in LaTeX; GitHub renders it)
labs/      runnable code, one folder per phase
datasets/  how to judge a world-model dataset, plus a catalog of the datasets used in the course
papers/    three-pass reading notes, each placed on the grid above
designs/   design docs for your own world models (Stage III)
answers/   check-question answers + feedback
```

Setup: `pip install -r requirements.txt`, then run labs from the repo root, e.g. `python3 labs/phase0/lab01_learning_is_estimation.py`.

*Data:* all generated by the labs themselves, plus [MNIST](datasets/README.md#tier-0-build-it-yourself) and Gymnasium CartPole.

### Phase 1: What is a world model? Classical roots (week 6) ⬜
Craik's mental models, Dyna, model-based vs model-free RL; state-space models, system identification, Kalman filter + MPC; anatomy of a modern world model.
*Lab:* pendulum with Kalman + MPC, then replace the dynamics with a learned MLP and plan with CEM.
*Data:* pendulum trajectories we generate ourselves; the first time *how* you collect data (random vs. controlled inputs) visibly changes what the model learns.

### Phase 2: Learning dynamics in state space (week 7) ⬜
PILCO, PETS (ensembles; epistemic vs aleatoric uncertainty), MBPO; compounding error, model exploitation, objective mismatch.
*Lab:* ensemble dynamics model on cartpole; error vs rollout horizon.
*Data:* [Gymnasium / MuJoCo locomotion](datasets/README.md#tier-1-low-dimensional-control-and-offline-rl) (PETS, MBPO); [D4RL / Minari](datasets/README.md#tier-1-low-dimensional-control-and-offline-rl) offline datasets (random / medium / expert), which show how the data-collecting policy sets what a model can be trusted on.

## Stage II: Data and model families (weeks 8–17)

Stage II opens with a phase on data itself, then works through each family of modern world models along with the datasets it was built on.

### Phase D: Data for world models (week 8) ⬜
Environments (simulators you can query) vs. logged datasets; what a world-model dataset must record (observations, actions, rewards, episode boundaries); who collected it (random, exploration, expert, human, the agent itself) and why coverage limits what can be learned; action-free video and how to recover actions (VPT's inverse-dynamics labelling, Genie's and LAPA's latent actions); the seven questions to ask of any dataset; formats (Gymnasium, RLDS, Minari, LeRobot); evaluation metrics (PSNR / SSIM / LPIPS, FVD, human-normalized score and IQM, downstream return), and why per-frame MSE metrics reward the blurry futures from Lesson 0.1.
*Lab:* build three toy datasets in one episode format (pendulum states, bouncing-ball pixels, fading-channel sequences); train the same dynamics model on random-policy and narrow-policy data and test both off-distribution.
*Data:* the [datasets guide](datasets/README.md) is the reading for this phase.

### Phase 3: Latent world models from pixels: the Dreamer line (weeks 9–10, core) ⬜
Ha & Schmidhuber (2018); PlaNet and the RSSM (sequential ELBO derived); DreamerV1 → V2 → V3; Dreamer 4 (2025).
*Lab:* mini-RSSM on a pixel environment; visualize dreams and drift.
*Data:* [DeepMind Control Suite](datasets/README.md#tier-2-pixel-based-rl-benchmarks) from pixels (PlaNet, Dreamer), [Atari](datasets/README.md#tier-2-pixel-based-rl-benchmarks), [Crafter](datasets/README.md#tier-2-pixel-based-rl-benchmarks) and [Minecraft](datasets/README.md#tier-3-games-and-video-for-generative-simulators) (DreamerV3); offline Minecraft gameplay (Dreamer 4).

### Phase 4: Decision-aware models (week 11) ⬜
MuZero, EfficientZero (V2); value equivalence, SPR, bisimulation; TD-MPC2.
*Lab:* tiny MuZero on a grid game or a TD-MPC-style planner.
*Data:* self-play in Go / chess / shogi (MuZero); [Atari 100k](datasets/README.md#tier-2-pixel-based-rl-benchmarks) (EfficientZero, SPR); DMC, Meta-World, ManiSkill2 and MyoSuite (TD-MPC2's 104 tasks).

### Phase 5: Sequence models and tokens (week 12) ⬜
IRIS, STORM, Δ-IRIS; Trajectory / Decision Transformer; DIAMOND; VQ-VAE, FSQ, video tokenizers.
*Data:* [Atari 100k](datasets/README.md#tier-2-pixel-based-rl-benchmarks) (IRIS, STORM, DIAMOND), [Crafter](datasets/README.md#tier-2-pixel-based-rl-benchmarks) (Δ-IRIS), [D4RL](datasets/README.md#tier-1-low-dimensional-control-and-offline-rl) (Trajectory / Decision Transformer).

### Phase 6: Generative world simulators (weeks 13–14, core) ⬜
Latent diffusion, DiT, flow matching; Sora's "world simulator" claim; UniSim, GameNGen, Oasis, WHAM/Muse, Matrix-Game 2.0; Genie 1 → 2 → 3; GAIA-1/2, Cosmos; drift and exposure bias (Diffusion Forcing, Self Forcing), real-time distillation (CausVid), long-horizon memory, controllability.
*Lab:* small action-conditioned diffusion world model on a toy 2D game; drift with and without diffusion-forcing noise.
*Data:* this is where data scale explodes. [VizDoom](datasets/README.md#tier-3-games-and-video-for-generative-simulators) agent play (GameNGen), 87 h of CS:GO (DIAMOND), 30k h of platformer video (Genie), ~7 years of Bleeding Edge play (WHAM), Minecraft (Oasis), 4,700 h of [driving](datasets/README.md#tier-4-driving) (GAIA-1), ~20M h of raw video (Cosmos).

### Phase 7: Predictive-representation world models: JEPA (week 15) ⬜
LeCun (2022); collapse prevention (EMA, VICReg); I-JEPA → V-JEPA → V-JEPA 2 / V-JEPA 2-AC; DINO-WM; generative vs non-generative debate.
*Lab:* latent MPC on frozen pretrained features.
*Data:* [Something-Something v2](datasets/README.md#tier-3-games-and-video-for-generative-simulators) and other web video (1M+ h for V-JEPA 2); under 62 h of [DROID](datasets/README.md#tier-5-robotics-and-embodied-video) robot video (V-JEPA 2-AC); PointMaze, Push-T, Wall, Rope, Granular (DINO-WM).

### Phase 8: Embodied world models (week 16) ⬜
World models as policy (UniPi), data engine (DreamGen, Cosmos), policy evaluator; UWM, GR-series, LAPA, Navigation World Models; NeRF / 3D Gaussian splatting, World Labs' Marble.
*Data:* [Open X-Embodiment, BridgeData V2, DROID, LIBERO](datasets/README.md#tier-5-robotics-and-embodied-video); [Ego4D](datasets/README.md#tier-5-robotics-and-embodied-video) egocentric video; robot navigation logs (Navigation World Models).

### Phase 9: LLMs and world models (week 17) ⬜
Othello-GPT, linear probes of space/time; Vafa et al. (2024, 2025); RAP, web-agent world models, Code World Model; Richens et al., *General agents need world models* (ICML 2025).
*Data:* [synthetic Othello games, Manhattan taxi routes, Blocksworld, WebArena / Mind2Web, Python execution traces](datasets/README.md#tier-6-language-and-symbolic-worlds).

## Stage III: New designs (weeks 18–23)

Stage III moves from studying world models to designing them: how to tell whether one is any good, what is still unsolved, and how to turn an idea into a tested design.

### Phase 10: Evaluation, open problems and the frontier (week 18, then ongoing) ⬜
Evaluation (Physics-IQ, physical-law studies, consistency, controllability, downstream usefulness); open problems (memory, causality, uncertainty, hierarchy, scaling, real-time cost, learned vs explicit physics); live literature sweep for work after mid-2026.
*Data:* [evaluation benchmarks](datasets/README.md#4-evaluation-metrics-and-benchmarks): Physics-IQ, Physion, VBench, WorldScore, WorldModelBench, Memory Maze.

### Phase 11: Design studio (weeks 19–20) ⬜
Turning an open problem into a design: place it on the grid, choose the variable to model and its distribution family, choose the data, state a hypothesis that could fail, pick the simplest strong baseline, plan ablations.
*Work:* write 2–3 short design docs with the [design template](designs/_template.md), run a cheap toy test of each, and choose one to take forward as the capstone.

### Track W: World models for the radio channel, and the capstone (weeks 21–23) ⬜
Channel / UE mobility as environment, CSI-RS / SSB measurements as observations, beam / MCS as actions. TR 38.843 use cases (CSI prediction, BM-Case1/2, CSI compression, positioning), LCM and model monitoring as world-model drift; Rel-19 and 6G AI-native direction; ray-tracing digital twins vs learned dynamics.
*Data:* [TR 38.901 CDL/TDL channels generated with Sionna or QuaDRiGa, DeepMIMO, DeepSense 6G, Sionna RT, DICHASUS](datasets/README.md#tier-w-the-radio-channel).
*Capstone:* by default, an RSSM-style model on TR 38.901 CDL/TDL channel sequences, predicting CSI / beam quality $k$ slots ahead and used for beam selection, vs Kalman / AR baselines. If a Phase 11 design is stronger, it replaces the default.
